## 1. 先读哪几份

第一次接手，按这个顺序读：

1. `docs/交接须知的注意文件.md`
2. `README.md`
3. `docs/项目进度.md`
4. `docs/接手升级手册-架构与路线.md`
5. `docs/部署说明.md`
6. `docs/学生端功能手册.txt`
7. `docs/教师端功能手册.txt`
8. `docs/评分说明.txt`

如果只关心模型隔离和改造边界，再看：

9. `docs/换热器融合方案设计.txt`
10. `server/models.js`
11. `server/config.js`
12. `server/engine-session.js`

## 3. 当前版本的文档基准

截至 2026-09-25，当前工程以以下事实为准：

| 项目 | 当前值 |
| --- | --- |
| 模型 | `tank` 三级液位、`hx` 换热器 |
| 内核 | `YunEngine`、`HxEngine`，分别构建、分别运行 |
| PID | `Ki = 1 / Ti`，`Ti=inf` 关闭积分，`Ti=0` 非法 |
| 状态隔离 | 液位与换热器目录、魔数、历史字段、云端槽位全部隔离 |
| 自动化门禁 | `npm run check`、`selftest_hx.exe`、`smoke-e2e.js` |
| 最近基线 | HX 48/48；smoke 155/155 |
| 线上状态 | 最新本地包装是否已部署，必须以服务器实际版本为准 |

## 4. 容易误解的旧结论

以下内容在旧文档中可能仍能看到，但已经不应作为当前判断依据：

- “换热器融合方案尚未实施”：现在已经有 `native-hx`、`HxEngine`、ModelSpec 和前端渲染器。
- “冷态不能保存”：当前已改为冷态或暂停可保存，仅运行中未暂停拒绝。
- “未知命令可能返回 500”：当前双模型协议和错误处理已做过整改，具体以当前测试为准。
- “换热器暂时没有 P&ID 布局”：当前已有 E1102、三路管线、圆泡仪表、KPI 顶栏、告警、水印和图例。
- “液位所有 P&ID 问题都已全面优化”：换热器 P&ID 已完成本轮整改，液位图仍属于后续专项优化范围。
- “发布包已经自动上线”：本地生成发布包不等于线上已部署，必须检查实际服务器。

## 6. 接手建议

1. 先读 `交接须知的注意文件.md`，不要先改历史报告里列出的旧问题。
2. 每次改动前先跑三门禁。
3. 先验证液位零回归，再验证换热器。
4. 模型差异优先放在 D1/D2/D3，不要扩散平台分支。
5. 改完代码后同步更新 `项目进度.md`、相关功能手册和交接文件。
6. 生成发布包后记录 SHA256；线上部署前先备份 `/opt/YunLevel/data`。
