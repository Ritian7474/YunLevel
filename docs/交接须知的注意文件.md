## 1. 先看结论

当前仓库已经完成双模型融合，核心功能可运行、已跑过自动化门禁。接手后第一件事不是改代码，而是先按本文第 3 节完成环境确认和测试复跑。

必须牢记的六条红线：

1. `tank` 模型的会话键、目录名、状态文件魔数、历史字段顺序不得改变。
2. `tank` 与 `hx` 的状态、历史、云端方案、教师备份必须保持隔离。
3. PID 统一使用 DCS 工业口径 `Ki = 1 / Ti`；`Ti=inf` 关闭积分；`Ti=0` 非法。
4. 模型差异优先放进 `server/models.js` 的 ModelSpec、内核目录或 P&ID 渲染器，禁止把 `if (modelId === 'hx')` 散落到平台业务层。
5. 修改前先备份；修改后必须同时通过 `npm run check`、HX 自检、`smoke-e2e.js`。
6. 未明确要求时，不自动部署线上服务器，不删除线上 `data/`，不执行 `docker compose down -v`。

以下动作必须按顺序执行。不要在没跑通测试之前改任何业务代码。

```powershell

```


```powershell

```

期望最后一行类似：

```text

```

```powershell

```

期望：


如果 `8097` 被占用，换一个端口。烟雾测试会使用临时数据目录，不应污染正式 `data/`。

### 3.6 手动启动本地服务

```powershell
npm start
```

或：

```powershell
.\start-server.bat
```

默认地址：

```text
http://127.0.0.1:8080
```

必须手动点一次：

1. 学生登录 `tank`，确认能进入控制、曲线、评分三个页面。
2. 教师登录 `tank`，确认看板和班级管理能打开。
3. 教师开放换热器，学生登录 `hx`。
4. `hx` 推荐工况 `TI1104 -> FV1102`，确认启动后能运行。
5. 切换曲线页，确认液位/温度、流量、开度三个标签都能用。
6. 回到冷态、暂停、保存、恢复上传保存状态至少各点一次。

## 4. 总体架构

```text
浏览器
  public/index.html
  public/app.js
  public/styles.css
        |
        | HTTP + SSE
        v
Node 网关
  server/server.js
  server/engine-session.js
  server/snapshot-store-v2.js
  server/roster-store.js
        |
        | stdin/stdout 文本命令
        v
C++ 内核
  tank: native/build/YunEngine.exe
  hx:   native-hx/build/HxEngine.exe
        |
        v
data/
  tank: state / history / submissions / teacher_backups
  hx:   hx-state / hx-history / hx-submissions / hx-teacher_backups
```

### 4.1 分层职责

| 层 | 目录 | 职责 | 允许的模型差异 |
| --- | --- | --- | --- |
| D1 仿真内核 | `native/`、`native-hx/` | 物理模型、PID、评分、命令协议 | 允许在内核文件中体现模型差异 |
| D2 P&ID 渲染 | `public/app.js` 渲染段、`public/styles.css`、`public/index.html` | 液位罐组图和换热器流程图的绘制 | 允许在渲染器中按模型分派 |
| D3 ModelSpec | `server/models.js` 和前端模型描述符 | 位号、历史字段、目录、会话键、导出字段 | 这是跨模型差异的首选落点 |
| 平台层 | `server/server.js`、登录、会话、SSE、班级、云端、评分记录 | 通用平台能力 | 禁止到处写 `if (modelId === 'hx')` |
| 通用前端 | `public/app.js` 大部分逻辑 | 控制卡、曲线、评分、教师看板 | 差异应通过 ModelSpec 数据驱动 |

### 4.2 为什么不能把模型判断散开

当前设计的目标是：新增模型时主要新增 ModelSpec 和渲染器，而不是在每个接口、每个按钮和每个导出路径里再写一遍判断。散落模型判断会导致：

- 液位旧数据被误读；
- 换热器方案被恢复到液位引擎；
- 教师看板、导出、评分混模型；
- 后续新增模型时漏改某一条路径。

## 6. PID 与评分口径

### 6.1 PID 红线

两个内核共用 `native/pid.cpp`，统一遵守 DCS 工业口径：

```text
Ki = 1 / Ti
```

规则：

- `Ti = inf`：关闭积分，`Ki` 趋于 0；
- `Ti = 0`：非法，必须拒绝；
- `Ti < 0`：按当前兼容口径映射为关闭积分；
- `NaN`：非法；
- 不允许把 `Ti=0` 当作“关闭积分”；
- 不允许把 `Ti` 放在分子上，即不能实现成 `Ki = Ti`；
- 前馈偏置是单独项，`u(t)` 不等于无条件把 P + I + D 当成最终输出；
- 关闭偏置时，输出只取反馈路径；开启偏置时才叠加偏置。

### 6.2 正反作用

- 正作用：PV 高于 SP 时，PID 输出向增大方向变化；
- 反作用：PV 高于 SP 时，PID 输出向减小方向变化；
- 三级液位典型液位回路通常使用反作用；
- 换热器推荐回路使用正作用；
- 修改方向判断时必须同时验证手工操作、自动回路和串级主副环。

### 6.3 评分

两个模型都使用四类权重：

```text
操作 20
控制 50
安全 20
效益 10
总分 100
```

评分期间：

- 只能在允许的冷态开始；
- 开始评分会清空回路和泵阀配置；
- 评分有结束时间和评分状态门禁；
- 未开始或未结束时不能进入评分结果页；
- 回到冷态会结束本轮评分；
- 评分记录由服务端保存，浏览器不能改分。

评分结束时间也会保存在内核状态中，结果页可显示。

## 7. 数据目录与持久化

默认数据目录：

```text
本地 Windows: <项目目录>\data
Docker:       /app/data
```

可通过 `YUN_DATA_DIR` 修改。

### 7.1 公共数据

| 文件或目录 | 内容 | 注意事项 |
| --- | --- | --- |
| `data/classes.json` | 班级、班级码、学生名单 | 不能随意手工改坏编码 |
| `data/settings.json` | 学生上传开关、双模型开放状态 | 教师端开关会写这里 |
| `data/runtime/` | 运行期辅助文件 | 不要当作备份源 |
| `data/score_records.jsonl` | 评分记录 | 教师可导出/清空 |

### 7.2 三级液位数据

| 目录 | 内容 |
| --- | --- |
| `data/state/` | 液位仿真状态快照 |
| `data/history/` | 液位曲线历史 |
| `data/submissions/` | 液位云端方案 1/2/3 |
| `data/teacher_backups/` | 教师读取学生方案前的备份 |

### 7.3 换热器数据

| 目录 | 内容 |
| --- | --- |
| `data/hx-state/` | 换热器仿真状态快照 |
| `data/hx-history/` | 换热器曲线历史 |
| `data/hx-submissions/` | 换热器云端方案 1/2/3 |
| `data/hx-teacher_backups/` | 换热器教师备份 |

### 7.4 快照语义

- 学生重新登录时默认先进入冷态，不会自动把上一次界面直接恢复；
- “保存当前状态”写的是当前快照；
- “恢复上传保存状态”恢复的是当前快照；
- 手动保存：冷态可以保存，暂停状态可以保存；
- 运行中且未暂停：拒绝保存并提示先暂停；
- 从云端方案或工程恢复后，统一为未启动状态；
- 状态文件恢复时会校验魔数，液位快照不能恢复到换热器，反之亦然；
- 曲线历史回到冷态不清空，只有“清空曲线”才清空历史；
- 自动恢复快照与手动当前状态不是同一件事，修改时要先查清楚调用链。

## 8. 班级、登录与会话

### 8.1 登录

登录请求必须带实验模型：

```json
{
  "role": "student",
  "model": "tank",
  "classCode": "班级码",
  "studentId": "学号",
  "name": "姓名"
}
```

教师登录：

```json
{
  "role": "teacher",
  "model": "tank",
  "teacherCode": "教师口令"
}
```

`model` 可选值为：

```text
tank
hx
```

### 8.2 学生隔离

- 每个学生一个独立内核会话；
- 会话键由班级、学号、模型共同决定；
- 同一学生重复登录时，旧登录令牌立即失效；
- 旧会话退出前会尽量保存恢复快照；
- 学生只能看到自己的状态、曲线、方案和评分记录；
- 教师演示会话独立，不进入学生在线列表，也不进入学生评分记录。

### 8.3 教师会话

- 一个总教师账号管理所有班级；
- 教师可按 `all`、`tank`、`hx` 查看模型数据；
- 教师读取某个学生的工程时，可在请求中显式指定模型；
- 读取跨模型方案后，教师认证会话会切换到对应模型引擎；
- 教师端始终可以直接进入两个模型，不受学生开放开关限制。

### 8.4 模型开放

- `tank` 默认开放；
- `hx` 默认关闭；
- 教师端“换热器模型：开放/关闭”控制学生是否能选择该模型；
- 修改开放状态后，学生登录页会动态显示/隐藏换热器选项。

## 9. 主要服务端文件

| 文件 | 作用 | 修改注意 |
| --- | --- | --- |
| `server/config.js` | 路径、端口、内核映射、数据目录 | 改目录前先确认旧数据迁移 |
| `server/models.js` | ModelSpec、历史字段、会话键、导出字段 | 双模型差异的首选位置，tank 字段不能改 |
| `server/engine-session.js` | 启动内核、发送命令、接收状态、写历史 | 历史字段按 ModelSpec 取，不要写死模型 |
| `server/server.js` | HTTP API、登录、教师接口、导出、SSE | 平台层不要乱写模型分支 |
| `server/snapshot-store-v2.js` | 当前状态、云端方案、工程导入导出、教师备份 | 线上实际使用 v2；不要只改旧 `snapshot-store.js` |
| `server/roster-store.js` | 班级和学生名单 | 导入 Excel/CSV 时注意编码 |
| `server/storage.js` | JSON 原子读写、哈希、目录工具 | 不要绕过原子写 |
| `server/zip-builder.js` | 批量 ZIP 导出 | 导出名称要带模型名 |

最常见错误之一：只修改 `server/snapshot-store.js`，但运行时实际加载的是 `server/snapshot-store-v2.js`。改快照逻辑前先全局搜索引用。

## 10. 主要前端结构与注意事项

### 10.1 页面布局

前端主要有：

```text
登录页
控制 / 仿真页
曲线页
评分页
教师看板
班级管理
云端数据 / 导出区域
```

主文件：

| 文件 | 作用 |
| --- | --- |
| `public/index.html` | 页面结构和固定控件 |
| `public/app.js` | 状态更新、交互、曲线、教师逻辑 |
| `public/styles.css` | 全部样式和 P&ID 外观 |

### 10.2 P&ID

- `#processVisual`：三级液位图；
- `#hxProcessVisual`：换热器 E1102 流程图；
- 两个图共用缩放/平移控制；
- `控制线` 按钮控制回路接线显隐；
- `次要标签` 按钮控制流量标签、图例和次要读数显隐；
- 缩放时标签使用 `--sim-label-scale` 做 0.86～1.20 的清晰度补偿；
- 全屏后拖动查看，不要恢复成滚动条拖动；
- 修改管道布局时必须检查有流量和无流量两种状态。

### 10.3 曲线

三个独立标签：

```text
液位 / 温度曲线
流量曲线
开度曲线
```

必须保留的能力：

- 点击位号图例隐藏/显示曲线；
- 三条曲线都能隐藏，不只是液位曲线；
- X 轴拖动缩放；
- Y 轴拖动缩放；
- 绘图区拖动平移；
- 标注线单独拖动，不能跟随光标乱跑；
- 标注开关控制标注线和时间标一起显隐；
- 时间标可单独拖动；
- 流量曲线 Y 上限可配置，最大不能超过当前模型阀门量程；
- “最新视图”和“清空曲线”不能误删；
- 教师查看学生曲线要尽量具备同样能力。

修改曲线逻辑时至少同时检查学生曲线页和教师看板曲线页，二者过去出现过功能不同步。

### 10.4 控制卡片

- 回路卡显示只读 PV；
- SP、Kp、Ti、Td、手动输出可编辑；
- 同一阀门不能同时被多个回路或串级占用；
- 已被回路占用的阀门不能在手操区直接修改；
- 同液位控制两个阀门时，SP 同步要只在修改时触发，不能实时覆盖用户输入；
- `Ti` 输入框必须允许 `inf`；
- 应用参数成功要给出明确反馈；
- 运行中不能切换单回路/串级；
- 单回路和串级卡片不能串数据。


```text

```

- 先打包本地 `YunLevel`；

- 备份远端 `/opt/YunLevel/data`；

- 该脚本会提示输入两次 SSH 密码；
- 部署期间会重建容器，学生正在使用时不要部署；
- 不要在服务器上执行 `docker compose down -v`；
- 不要删除 `/opt/YunLevel/data`；
- 如果 SSH 连接超时，先检查阿里云安全组是否放行 22，以及当前电脑出口 IP 是否变化；
- 如果 8080 页面打不开，先检查安全组和 `docker compose ps`。

## 16. 常见故障排查

### 16.1 页面打不开

先看服务：

```sh
curl http://127.0.0.1:8080/api/health
cd /opt/YunLevel
docker compose ps
docker compose logs --tail=200 yunlevel
```

如果是公网访问失败但本机 curl 正常，通常是：

- 阿里云安全组没有放行 `8080/8080`；
- 当前公网 IP 已变化；
- `ufw` / `firewalld` 拦截；
- 容器没有监听。

### 16.2 提示 `engine exited`

```sh
docker compose exec yunlevel ls -lh /app/bin
docker compose logs --tail=200 yunlevel
```

缺少任一内核：

```sh
docker compose up -d --build
```

如果只有 `YunEngine` 没有 `HxEngine`，编译阶段已经失败，不是前端问题。

### 16.3 换热器打不开

依次检查：

1. 教师端是否开放换热器；
2. `/app/bin/HxEngine` 或本地 `native-hx/build/HxEngine.exe` 是否存在；
3. 登录请求是否带 `model: "hx"`；
4. 是否误把液位快照恢复到 HX；
5. 浏览器是否缓存旧前端，可强制刷新。

### 16.4 曲线功能没有恢复

先区分：

- 学生曲线页；
- 教师看板曲线页。

两者过去曾各自修过，不能只测其中一个。检查 `public/app.js` 中学生曲线和教师曲线两组事件绑定。

### 16.5 保存失败

当前规则：

- 运行中且未暂停：拒绝；
- 冷态：允许；
- 暂停：允许；
- 教师和学生应一致。

如果点击无反应，检查 `/api/current/save` 请求和浏览器控制台。

### 16.6 从云端恢复后不是冷态

当前产品要求：从云端方案或工程恢复后统一为未启动状态。若出现运行中，检查快照恢复接口是否在恢复后发送了 `RESET`，以及内核状态文件是否被覆盖。

### 16.7 页面显示旧样式

前端没有构建哈希。使用 `Ctrl+F5` 或关闭旧标签页重新打开。必要时检查服务器解压时间与发布包 SHA256。

### 16.8 评分页打不开

评分页有门禁：未开始或未结束不能进入结果页。先确认评分方案已选择、已开始，并且已经到结束时间。

### 16.9 时间不对

Docker 容器默认可能是 UTC。需要北京时间时，在 `docker-compose.yml` 添加：

```yaml
environment:
  TZ: Asia/Shanghai
```

然后：

```sh
docker compose up -d
```

## 18. 明确禁止或谨慎执行的操作

### 18.1 禁止

- 禁止改变 `tank` 的目录名、会话键格式、魔数、历史字段顺序。
- 禁止让 `tank` 和 `hx` 共用一个状态快照目录。
- 禁止把 `Ti=0` 解释成关闭积分。
- 禁止使用 `Ti` 做分子计算积分项。
- 禁止把 `data/`、测试数据、临时文件打进发布包。
- 禁止执行 `rm -rf`、`docker compose down -v`、删除数据卷。
- 禁止在未备份线上数据的情况下重建或清空容器数据。
- 禁止把服务器 root 密码、学生信息或真实班级名单写进源码、文档或发布包。
- 禁止把测试用默认教师口令当成正式口令。
- 禁止在没有测试通过的情况下覆盖线上版本。

### 18.2 谨慎

- `deploy-yunlevel.ps1` 无参数会直接上传并重建线上容器；
- `docker compose down` 只停容器，不停 ECS，仍可能计费；
- `RESET` 会清空回路和运行状态；
- 评分开始会清空配置；
- 导入班级名单时“覆盖导入”会替换原名单；
- 教师读取学生方案前会覆盖教师当前状态，修改这条逻辑时要保留教师自动备份。

## 19. 当前已知风险与待确认项

1. 线上 ECS 可能还没有部署最新双模型发布包，部署状态必须以实际服务器为准。
2. `docker-compose.yml` 中仍然有默认教师口令示例，正式使用必须更换。
3. 当前是 HTTP + 公网 IP 测试版，没有 HTTPS，没有个人密码体系；所有数据对服务器管理员可见。
4. 数据目录没有额外加密，服务器拿到 root 权限即可读取学生状态和评分。
5. 项目没有 Git 仓库，改错后不能依赖 `git diff` 或 `git restore` 回滚。
6. 自动化覆盖更新机制已有门禁，但 UI 的鼠标拖拽、缩放、多浏览器窗口仍建议人工回归。
7. Docker 镜像必须同时包含两个内核；只验证液位内核不够。
8. 发布包与线上数据分离，恢复线上数据不能只解压源码包。
